## 1. Требования

Перед установкой убедитесь, что на компьютере установлено:

| Программа | Где скачать |
|-----------|-------------|
| .NET SDK 10.0+ | https://dotnet.microsoft.com/download |
| PostgreSQL 16+ | https://www.postgresql.org/download/windows/ |

PostgreSQL должен быть установлен под пользователем **postgres** (стандартный суперпользователь).

## 2. Установка базы данных

> Выберите один из двух способов установки БД.

> **Важно:** создание таблиц и наполнение данными через SQL-скрипты пока не предусмотрено.  
> Структура и данные загружаются только через импорт из готового дампа (`install\backup-ktgs_maxdb-prod.sql`).

---

### Способ 1 — Быстрый импорт через скрипты

#### Шаг 1 — Настроить параметры БД

Откройте файл `install\db_settings.bat` и проверьте переменные:

```batch
DB_SUPER_USER=postgres        :: суперпользователь PostgreSQL
DB_NAME=ktgs_maxdb4           :: имя рабочей базы данных
DB_NAME_DEV=ktgs_maxdb4_dev   :: имя базы для разработки
BACKUP_FILE=backup-ktgs_maxdb-prod.sql
PG_DUMP_PATH=                 :: путь к папке bin PostgreSQL (если не добавлен в PATH)
```

Если PostgreSQL добавлен в PATH при установке, `PG_DUMP_PATH` оставьте пустым.  
Если нет — укажите путь, например: `PG_DUMP_PATH=C:\Program Files\PostgreSQL\16\bin\`

#### Шаг 2 — Создать базу данных

Запустите от имени администратора:

```
install\create_db.bat
```

Скрипт создаёт базу данных `ktgs_maxdb4` под пользователем `postgres`.

#### Шаг 3 — Восстановить данные из дампа

Запустите от имени администратора:

```
install\restore_db_from_backup.bat
```

Скрипт загружает все данные из `install\backup-ktgs_maxdb-prod.sql` в базу `ktgs_maxdb4`.

---

### Способ 2 — Ручное создание через psql

#### Шаг 1 — Создать БД и пользователя

Следуйте инструкции в файле `install\sql\create_db.sql`.

#### Шаг 2 — Восстановить данные из дампа

Запустите от имени администратора:

```
install\restore_db_from_backup.bat
```

Скрипт загружает все данные из `install\backup-ktgs_maxdb-prod.sql` в базу `ktgs_maxdb4`.

## 3. Настройка проекта

### Установить зависимости

> Выберите один из двух способов.

**Способ 1 — dotnet CLI:**

```
dotnet restore
```

**Способ 2 — батник:**

Сначала откройте `bat_settings.bat` и убедитесь, что переменные заданы верно:

```batch
set APP_DIR=           :: папка с .csproj (если в корне — оставьте пустым)
set APP_NAME=ktgs_bot  :: имя .csproj без расширения
```

Затем запустите:

```
install_net.bat
```

Батник проверит наличие .NET SDK и загрузит NuGet-пакеты из `.csproj`.

### Настроить подключение к БД

1. Скопируйте файл примера конфигурации:

```
copy appsettings.example.json appsettings.json
```

2. Откройте `appsettings.json` и задайте строку подключения:

```json
{
  "Bot": {
    "Token": "ВАШ_ТОКЕН_БОТА"
  },
  "Database": {
    "Host": "localhost",
    "Port": 5432,
    "DBName": "ktgs_maxdb4",
    "Username": "postgres",
    "Password": "ВАШ_ПАРОЛЬ"
  }
}
```

Замените `ВАШ_ПАРОЛЬ` на пароль пользователя `postgres`, заданный при установке PostgreSQL.

> Файл `appsettings.json` не хранится в репозитории (добавлен в `.gitignore`) — не передавайте его другим.

## 4. Запуск в консоли

> Выберите один из двух способов.

**Способ 1 — dotnet CLI:**

```
dotnet run
```

Или сначала соберите, затем запустите exe:

```
dotnet build
bin\Debug\net10.0\PostgresApp.exe
```

**Способ 2 — батник:**

```
run.bat
```

Батник собирает и сразу запускает проект. Поддерживает необязательные аргументы (порядок не важен):

| Аргумент | Что делает |
|----------|------------|
| `debug`  | Сборка в конфигурации Debug (по умолчанию — Release) |
| `dev`    | Запуск в контуре Development (по умолчанию — Production) |

Примеры:

```
run.bat                 :: Release / Production
run.bat debug           :: Debug / Production
run.bat dev             :: Release / Development
run.bat debug dev       :: Debug / Development
```

## 5. Сборка и публикация через батники

Батники для управления сборкой. Все они читают настройки из `bat_settings.bat` — перед первым использованием убедитесь, что `APP_DIR` и `APP_NAME` заданы верно (см. [раздел 3](#3-настройка-проекта)).

### build.bat — скомпилировать проект

```
build.bat           :: сборка Release
build.bat debug     :: сборка Debug
```

Аналог `dotnet build --configuration Release`.

### publish.bat — создать standalone .exe

```
publish.bat
```

Создаёт один `.exe` файл без внешних зависимостей в папке `publish\`.  
Целевая платформа — Windows x64. Аналог:

```
dotnet publish --configuration Release --runtime win-x64 --self-contained true -p:PublishSingleFile=true
```

### clean.bat — удалить временные файлы

```
clean.bat
```

Запрашивает подтверждение, затем удаляет `bin\`, `obj\`, `.vs\` внутри папки проекта и папку `publish\` в корне.  
Аналог `dotnet clean`, но также удаляет `publish\`.

## 6. Запуск в VS Code

1. Откройте папку `PostgresApp` в VS Code: **File → Open Folder**
2. Установите расширение **C# Dev Kit** (`ms-dotnettools.csdevkit`)
3. Нажмите `F5` — выберите профиль **.NET: PostgresApp**

Приложение запустится в встроенном терминале.

---

## 7. Запуск в Visual Studio

1. Откройте файл проекта: **File → Open → Project/Solution** → выберите `PostgresApp.csproj`
2. Нажмите `F5` или кнопку **Запустить** на панели инструментов

## 8. Тесты

Отдельного тестового фреймворка нет. Проверка работы — через ручной запуск приложения.

При запуске программа последовательно вызывает все методы и выводит данные из БД:

- Ближайшие дни открытых дверей
- Список филиалов колледжа
- FAQ по поступлению
- Список специальностей
- Карточка специальности
- Информация о переводе

Логи тестовых запусков сохраняются вручную в папке `tests/` в формате `test_YYYY-MM-DD.txt`.
